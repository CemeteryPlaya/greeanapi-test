# GREEN-API Чат

Тестовое задание «Фронтенд-разработчик React»: веб-интерфейс для отправки и получения текстовых сообщений через [GREEN-API](https://green-api.com). Внешний вид — по мотивам [web.max.ru](https://web.max.ru/).

Из-за региональных ограничений вместо MAX поддерживаются **WhatsApp** и **Telegram** — мессенджер выбирается на экране входа. Методы GREEN-API у них одинаковые, отличается только адресация чатов (см. «Устройство»).

## Возможности

- вход по `idInstance` и `apiTokenInstance` (и `apiUrl` инстанса), проверка через `getStateInstance`;
- выбор мессенджера: WhatsApp или Telegram;
- создание чата по номеру телефона получателя;
- отправка текстовых сообщений — метод [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/);
- получение входящих — [технология HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/): `ReceiveNotification` → обработка → `DeleteNotification`;
- статусы исходящих (отправлено / доставлено / прочитано), счётчик непрочитанных, поиск по чатам;
- история чатов сохраняется в `localStorage` браузера; светлая и тёмная тема; мобильная вёрстка.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev      # http://localhost:5173
```

Прочие команды:

```bash
npm test         # юнит-тесты (Vitest)
npm run build    # проверка типов + production-сборка в dist/
npm run preview  # просмотр собранной версии
```

Для разработки форму входа можно заполнять автоматически: скопируйте `.env.example` в `.env.local` и впишите данные инстансов — отдельно для WhatsApp (`VITE_GREEN_API_WHATSAPP_*`) и Telegram (`VITE_GREEN_API_TELEGRAM_*`). При переключении мессенджера на экране входа подставляется соответствующий набор. Работает только в `npm run dev`, в production-сборку значения не попадают; `.env.local` в `.gitignore`.

## Деплой на Vercel

Проект — статический сайт на Vite, сервер не нужен.

1. Импортируйте репозиторий в [Vercel](https://vercel.com/new) — пресет **Vite** определится сам (Build Command `npm run build`, Output Directory `dist`).
2. Переменные окружения **не задавайте**: всё с префиксом `VITE_` попадает в публичный JS-бандл, и токен увидит любой посетитель. Пользователь вводит свои данные на экране входа.

## Подготовка инстанса GREEN-API

1. В [личном кабинете](https://console.green-api.com) создайте инстанс WhatsApp или Telegram и авторизуйте его.
2. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance`.
3. В настройках инстанса **включите получение уведомлений** о входящих сообщениях (и, по желанию, о статусах и исходящих) и оставьте **пустым URL вебхука** — иначе уведомления уйдут на вебхук и не попадут в очередь HTTP API.

## Как пользоваться

1. Откройте приложение, выберите мессенджер и введите параметры инстанса.
2. Нажмите «Новый чат» (карандаш), введите номер получателя, например `+7 999 123-45-67`.
3. Напишите сообщение и нажмите Enter (Shift+Enter — перенос строки).
4. Ответ собеседника появится в чате автоматически.

## Устройство

```
src/
  api/greenApi.ts              клиент GREEN-API (fetch, без зависимостей)
  lib/platforms.ts             различия WhatsApp и Telegram: поиск chatId по номеру
  hooks/useNotificationPolling цикл receiveNotification → deleteNotification
  lib/notifications.ts         разбор уведомлений в события чата
  store/chatReducer.ts         состояние чатов и сообщений (useReducer)
  lib/storage.ts               сохранение в localStorage
  components/                  экран входа, список чатов, окно чата
```

Несколько решений, которые стоит пояснить:

- **WhatsApp:** чат адресуется `номер@c.us`. Номер проверяется методом `CheckWhatsapp`, но его `chatId` не используется — он может быть вида `…@lid`, а входящие (без включённого lid-режима инстанса) приходят с `номер@c.us`. Если включить lid-режим, ответы будут приходить в отдельный чат.
- **Telegram:** `chatId` личного чата числовой. Поэтому номер сначала проверяется методом `CheckAccount`, который возвращает настоящий `chatId` — с ним приходят и ответы. Если `CheckAccount` недоступен, чат создаётся с `номер@c.us`, а при первом ответе переносится на настоящий `chatId` по `senderPhoneNumber`.
- **Уведомление удаляется из очереди всегда**, даже если оно не про текстовое сообщение, — иначе очередь «застрянет» на нём.
- **Без дублей:** своё отправленное сообщение сразу показывается со статусом «отправляется», а пришедшее позже уведомление `outgoingAPIMessageReceived` с тем же `idMessage` повторно не добавляется.
- Учётные данные хранятся только в `localStorage` браузера и отправляются только в GREEN-API.
